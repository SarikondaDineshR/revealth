# Revealth v0.2 Freeze Notes

## Purpose

v0.2 stabilizes the v0.1 governed demo path for Codespaces, improves operator visibility, and hardens future live-execution safety boundaries without enabling live execution.

## Milestone 1: Codespaces-First Reliability

- Added `corepack pnpm demo:doctor`.
- Improved `demo:bootstrap` environment checks.
- Added explicit Docker, Compose, and buildx timeout classification.
- Validated safe `.env` defaults for demo use.
- Updated Codespaces bootstrap guidance.

## Milestone 2: Control-Plane Usability

- Added Demo Status and Readiness Summary.
- Added Approval Queue and Execution Run Inspection.
- Added audit timeline filter chips.
- Improved blocked/readiness messaging.
- Expanded UI helper and render tests.

## Milestone 3: Future Live-Execution Safety

- Strengthened path and command validation.
- Rejected wildcard allowed-file scopes and shell control operators.
- Added immutable contract snapshot verification.
- Added executor manifest integrity checks.
- Persisted preflight summaries into execution logs.
- Added live execution approval checklist.

## Current Capabilities

- Governed idea-to-execution-run planning chain.
- Durable Temporal workflows.
- Structured artifacts, approvals, lineage, audit logs.
- GitHub issue dry-run records.
- Codex task packets, Git execution plans, execution contracts.
- Dry-run execution lifecycle and control-plane observability.

## Safety Guarantees

- Live execution remains blocked.
- Executor does not mutate repository files.
- No automatic branch creation or PR creation.
- External side effects remain approval-gated and dry-run protected.
- `.env`, `.revealth/`, and generated runtime files remain ignored.

## Known Limitations

- Docker/buildx health can still block local container rebuilds.
- Control-plane audit filters are visual summaries, not interactive query controls.
- Future live execution readiness remains preparatory only.

## Operational Risks

- Docker Desktop or Codespaces Docker can hang before `loading Dockerfile`.
- Dirty worktrees can block readiness checks.
- Misconfigured `.env` can block demo smoke.
- Live execution requires a separate isolation and approval design pass.

## Commands

Doctor:

```powershell
corepack pnpm demo:doctor
```

Demo and smoke:

```powershell
corepack pnpm demo:smoke
```

## Intentionally Blocked

- Live Codex execution.
- Repository mutation by executor.
- Automatic branch creation.
- Automatic pull request creation.
- Production deployment.
- Customer-facing automation.
- Secret access or real password storage in demo flows.

## Recommended v0.3 Direction

Focus on demo reproducibility, richer control-plane inspection, and a formally isolated execution-runner design. Do not enable live execution until the isolation model, approval checklist, and rollback path are reviewed.
